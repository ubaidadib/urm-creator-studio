# Audio, voice and captions

## Captions workflow (speech in the video)
0. While analysing (before planning), transcribe the source clip — `studio.py transcribe <file>` writes
   `<file>.draft.srt` — to learn what is said and plan the edit around it. If the final video uses that clip
   untrimmed as the first content scene, these timings can be used directly for captions.
1. Otherwise, after the cut is final, render once **without** captions (preview is fine).
2. `studio.py transcribe <project> --language ar` (or `en`/`auto`) — timings match the edited video. Uses whisper.cpp locally; nothing is
   uploaded. Output: `captions/transcript-draft.srt` + `.review.json` (detected language, flagged count).
   Segments the model is unsure about end with `[؟]`/`[?]`.
3. **Review with the user** — show the text cue by cue (or the whole text for short videos) and ask them to
   correct names, numbers, and every flagged line. If audio is unclear, say so; never guess words.
   **Zero flagged lines does not mean correct.** Speech recognition can be confidently wrong (tested: it heard
   «قهوة» as «تهوى» and wrote «وأستمتعوا» instead of «واستمتعوا» with high confidence). Before showing the draft,
   read it yourself and point out words that don't fit the context or the brand ("I think «تهوى» should be
   «قهوة» — correct?"), and check hamza/taa marbuta spelling. Never change words silently; propose, then
   let the user decide.
   If speech is mostly unintelligible, tell the user and suggest re-recording or typing the script.
4. Save the approved text as `captions/<lang>.srt` (you can write SRT directly), run
   `captions check <file>` and fix problems (`captions reflow` splits long cues).
5. Set `"captions": {"src": "captions/ar.srt", "burn": true}` and render. The sidecar `captions.srt`/`.vtt`
   are also exported for platforms that accept subtitle files.

Without speech-to-text installed: offer (a) the user types or pastes the script and you time it with
them, or (b) install whisper.cpp (ask first; explain the download size, ~1.6 GB for the best Arabic model).

## Bilingual / translated captions
- "Mixed video with Arabic subtitles": transcribe in the spoken language, translate faithfully into Arabic
  yourself, mark it as a translation, and have the user approve. Keep timing from the original cues.
- Two caption languages at once: burn one (usually Arabic), export the other as `.srt` only, or make two
  versions of the video (render twice with different `captions.src` and `output_name`).
- Translation quality: natural MSA, not literal; keep names; numbers in the brand's numeral style.

## Music
- Only music the user owns or is licensed to use (their purchase, YouTube Audio Library under its terms,
  a composer's permission). Record the source in your notes to the user. Never fetch music yourself.
- Volume 0.12–0.2 under speech, 0.3–0.5 for music-only videos. `duck: true` lowers music automatically
  when there is speech or voiceover. Fades: 1 s in, 2 s out (automatic).
- Beat-synced editing (Pro): find beat times by listening points the user gives, or by `inspect` cut
  points of a music video; place scene boundaries on them.

## Sound effects
`audio.sfx: true` adds a soft, synthetic whoosh on transitions (generated by the engine, licence-free).
Use for energetic videos only.

## Voiceover
- Real voice (preferred): the user records on their phone (quiet room, 20 cm from mouth); add as
  `audio.voiceover`; lower original audio with `original_volume`.
- Synthetic narration: only after explicit approval for this video. Tell the user it is a computer voice
  and that platforms may require labelling AI-generated audio. macOS system voice:
  `voiceover script.txt media/vo.wav --language ar --approved` (Arabic voice «Majed»). Never imitate a
  real person's voice; no voice cloning.
- Replacing original audio (muting the speaker, changing music in a recording) requires approval first.

## Loudness & intelligibility
- Final mix is normalised to −14 LUFS integrated, true peak ≤ −1.5 dBTP (social/YouTube standard).
- QC warns outside −16.5…−11.5 LUFS. If speech is hard to understand: raise speech clip `volume`, lower
  music, enable `duck`, or ask for a better recording. Never claim audio is clear if you have not checked
  the loudness result and the user hasn't heard it.
